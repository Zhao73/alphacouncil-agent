# v1.9.0 — Model selection and terminal navigation

This source release candidate makes model connections discoverable and keeps terminal
navigation, editing and saved research easier to use. Publication and installed-release
acceptance are separate from this document's implementation scope.

## Release scope

| Area | Change | Boundary |
| --- | --- | --- |
| Codex models | Query the bundled official runtime through its app-server `model/list` protocol and display model names and the default selection. | The runtime owns login. The client does not read or copy OAuth tokens, and listing models does not run research. |
| API models | Read the selected service's model list where supported. Show GLM models sourced from documentation as documentation candidates. | A catalog entry is not proof that the current account can use that model. Capability checks still apply before research. |
| Connection setup | Add DeepSeek, Kimi International/China, GLM International/China, OpenRouter and OpenCode Zen/Go presets alongside Codex, OpenAI, Anthropic and custom compatible APIs. | Each service still requires its own supported access method. A preset does not grant a subscription or API credit. |
| Gateway protocols | Match documented gateway models to Chat Completions, Responses or Messages transport and persist the chosen format. | Unsupported or undocumented model/protocol combinations cannot be assumed compatible. |
| Login feedback | Distinguish a timeout, user cancellation, process failure and an unverified login status. | Saving connection metadata does not itself prove authentication. A failed status check never counts as a successful login. |
| Navigation and editing | Keep mouse navigation fixed; edit inputs with a real cursor and save or cancel on the same page. Preserve the reading position through history, search and back navigation. | Terminal behavior needs separate verification at supported dimensions and on each packaged platform. |
| Mouse input | Parse escape sequences split across input chunks and guard against unintended click actions. | Automated input tests and an actual installed terminal session provide different evidence. |
| Research reading | Show run progress and open saved evidence, method statements, individual debate rounds and complete reports. | The reader exposes saved deliverables, not private model reasoning. Missing or failed work keeps its recorded status. |

## Account and plan boundaries

Codex uses the official runtime's supported login and the access available to that account.
Other model services use their own API credentials. AlphaCouncil does not extract subscription
tokens or turn a web or coding subscription into unrestricted API access.

Kimi Code and GLM Coding Plan entries explain their intended use; they are not general
stock-research connection presets. OpenCode Go is presented with its plan-use notice, and
Zen/Go transport selection follows the documented endpoint/model combination. The client
must still respect the service's current access and usage terms. Provider labels, model
lists and transport checks do not establish permission for every workload.

Research continues to require the existing tool loop, sources, structured output, request
and token budgets, cancellation and report validation. Adding a model or gateway does not
relax the selection receipt, evidence coverage, method admission or PM rating contract.
All 26 provisional PersonaPacks remain version 0.9.4; none is promoted to a validated
`method_model` by this release.

## Archive startup

After publication and extraction of the archive matching the system, run
`./alphacouncil` on macOS or Linux. In Windows PowerShell, run
`.\alphacouncil.cmd`. Native archives include Node and the official Codex runtime;
users still need the selected model service's account or API access. Availability and
downloaded-install validation of the 1.9.0 archives must be verified at publication.
