# v1.7.0 — Research setup, calculation and reading upgrade

This release improves research setup, calculations, data checks and report reading. It keeps all
26 provisional operator lenses available and preserves the current PM rating rubric. It does
not claim that more Buy ratings, fewer selected methods or additional providers improve returns.

## Shipped behavior

| Area | Change | Boundary |
| --- | --- | --- |
| Setup | Show the named configuration first; preserve the full expandable catalog. Remember compatible choices for the same symbol, mode, language, objective and horizon. | A fresh submission and receipt are required. Explicit choices win. A changed catalog invalidates the prefill. |
| Horizon | The host proposes a disclosed 12-month default for directional requests without a period. | Other objectives and explicit horizons are not overwritten. |
| Method selection | Check manifest requirements plus eligibility, veto, scoring and tool inputs before recommending. | This proves input-ID coverage, not factual accuracy, timely publication or policy eligibility. Execution still validates those. |
| Cash-flow proxy | Divide cumulative FCF by the actual annual observation count before comparing the historical annual yield with market value. | Missing years cannot be guessed. Historical average annual FCF is not current TTM FCF. The Wood revenue-growth hurdle remains a project-authored proxy. |
| Simons lens | A large session move is `unusual_session_move`, with a cautious stance. | It is neither a backtested signal nor evidence of a deployable edge. |
| Headless cost | Retain a hashed frozen abstention and its deterministic explanation without another voice call. | Scored methods keep their isolated workers. Visible-host returned workers still must complete. No fixed speedup or call count is promised. |
| Reports and GUI | Lead with the conclusion and key decision information; preserve expandable evidence and every selected method statement (expanded text in hosts that do not support HTML details). Open the concise handoff first; add run search and phase/count/elapsed progress. | Saved evidence, ordered markers and run-integrity requirements remain intact. |
| Price history | Request up to ten years, disclose actual coverage and maximum observed drawdown; cache successful histories for one hour with original timestamps. | Current adjusted history is not a historical information vintage, valuation series or IV history. |

The public-data path introduces no new runtime dependency, API key or separately installed data
client. The existing transitive dependencies `fast-uri` (development) and `qs` (Work gateway) are updated.
`npm run doctor` exposes the existing installation diagnostic.

## Data-source follow-up

The following integrations are **not shipped** in v1.7.0:

- **Moomoo REST:** the provider documents an HTTP API, so OpenD is not inherently required for
  this route. OAuth/API credentials, access eligibility, region coverage and rights to serve
  users still need confirmation. A backend service could remove client setup only after those
  requirements are met. News metadata/links do not establish licensed full-text or historical
  archive coverage. See [official getting started](https://open.moomoo.com/api/overview/getting-started).
- **TradingView:** evaluate [tradingview-mcp](https://github.com/atilaahmettaner/tradingview-mcp)
  and [TradingView-API](https://github.com/Mathieu2301/TradingView-API) as optional acquisition
  candidates after protocol, attribution and permitted-use validation. Neither repository
  establishes licensed production data rights. Do not bundle user sessions or promise an
  anonymous production feed before verifying it.
- **Historical research data:** prioritize dated financial observations, earnings expectations
  and news publication timestamps. A ten-year price chart cannot supply historical fundamentals,
  and replay evaluation must use information actually available at each cutoff.

Before another provider enters the default path, verify a real authenticated request where
required, timestamp/currency/adjustment semantics, failure behavior, usable coverage and the
right to provide the resulting service. Keep optional-provider failure from breaking basic
public-data research. These are implementation prerequisites, not a request for users to
install or configure another application.

## Validation and remaining evidence

The release checks cover calculation and selection regressions, fresh-confirmation behavior,
cache timestamps and cutoff handling, deterministic policy execution, report completeness,
headless worker boundaries, source/package parity and existing gateway tests. Generated
machine simulations remain synthetic: no human reference, no effective sample size and no
formal experiment effect. The v1.7 policy and simulation baselines change only for the
documented cash-flow and Simons corrections; thresholds are not broadly relaxed.

Performance/decision-quality evaluation is still required before changing Buy thresholds or
claiming an optimal panel size: freeze cases and available information, compare the baseline
against data-only and selection changes separately, measure missing-input and abstention causes,
and track latency, cost, sourced errors and subsequent outcomes. Human source/formula approval,
validated method-model status and live multi-host completion are separate from package release.

When neither instrument classification nor coverage is supplied, Stage 0 proposes a labelled
`starter_pending_data` configuration (eight methods in full, four in quick). It is not a
data-backed recommendation: the advisory recommendation remains `not_evaluable`, and actual
method applicability is checked after evidence arrives. Explicit, remembered or data-supported
choices take precedence. The starting size is a usability choice, not a validated optimum.

Local release validation: `npm run check` passed with 1,655 tests; the Work gateway passed
5 tests; both dependency audits reported zero known vulnerabilities. GUI behavior was
checked using a clearly labelled synthetic run. A real AAPL request returned 2,514 sessions
from 2016-09-06 through 2026-09-04; a second request used the cache with the same observation
timestamp. These checks do not establish live council completion or investment efficacy.
