## Release outcome

The formal production outcome remains 26 auditable method seats differentiated by what they
research, compute, reject and remember, not by imitating a famous person's tone. The current
0.9.0 solo-test channel proves only that 26 provisional operator lenses can be built, loaded
and executed through the same catalog/runtime shape. It does not prove attributed methods,
operational admission or production eligibility.

The release does not describe 26 opinions as 26 independent samples. It records shared-model,
shared-evidence and shared-source correlation, preserves minority reports, and reports
effective diversity only after measured ablations.

## Mandatory run sequence

```text
begin_council_selection
-> display every numbered selector card
-> user submits 1..N / ranges / stable IDs / all
-> confirm_master_selection(display_ack=true)
-> consume one-run selection_receipt
-> freeze point-in-time fact pack
-> evidence analysts
-> selected PersonaPack v3 methods
-> verifier / refuter pass
-> anonymous bull-bear challenge
-> portfolio risk and decision
-> report, episode ledger and later postmortem
```

`screen`, `options`, `news` and `market` remain pure-data routes and do not open a council
selection. If one of those routes expands into an investment judgment, it must stop and enter
the selection sequence first.

## Selector contract

Every enabled pack must supply localized selector content:

```json
{
  "id": "master_buffett",
  "index": 2,
  "identity": "Who this method represents",
  "method": "What it does differently",
  "best_for": "Where it is useful",
  "maturity": "prompt_lens | operator_lens | operational | candidate | method_model",
  "native_decision": "schema id",
  "relative_seat_cost": 1
}
```

Rules:

- The server assigns numbers from a frozen catalog snapshot; a host never reorders them.
- A request that names people passes their stable IDs as preselection, then still displays
  the complete catalog and requires a submission.
- Empty selections are invalid for a council run. `all` resolves to explicit IDs in the
  receipt rather than remaining a boolean.
- Catalog, prompt/language intent and symbol are bound into the receipt. A receipt is
  short-lived, atomically consumed and idempotent only for the same run ID.
- Claude Code, Codex, OpenCode and Grok share numbered text as the baseline. Native
  multi-select is optional enhancement, never a dependency.

## PersonaPack v3 contract

Each pack contains eight independently reviewable layers:

1. Identity and maturity: stable ID, public label, corpus hash, source cutoff and explicit
   `prompt_lens | operator_lens | candidate | method_model` status.
2. Corpus: exact primary-source anchors, doctrine propositions, decisions, failures,
   reversals and counterfactuals. Homepages and publisher product pages do not prove rules.
3. Research planner: private queries, required fact types, disconfirming searches, source
   admission policy and budget.
4. Typed computations: registered tools only; every input carries value, unit, period,
   `public_at` and lineage.
5. Decision policy: eligibility, hard vetoes, qualitative rubrics, native output and a
   deterministic common projection.
6. Calibration and abstention: missing facts lower coverage or return `out_of_scope`; prose
   cannot manufacture a score.
7. Memory and postmortem: both time clauses apply - `public_at <= as_of` and
   `memory_created_at <= as_of`; no outcome is graded before its horizon.
8. Voice: loaded only after the anonymous decision freezes. Name or tone cannot move the
   underlying judgment.

## Revision 1 admission and measurement clarifications

### Corpus counts are an inventory, not a `method_model` promotion rule

The old v2 inventory vector of 25 doctrine propositions, 5 primary sources, 5 decisions,
3 failures, 10 vetoes and 10 counterfactuals is not a `method_model` admission gate. In v3,
10 counterfactuals satisfy only the operational floor; a candidate needs 20. Even a pack that
meets every corpus count remains no more than candidate-eligible until name/voice and policy
swaps, grounded counterfactuals, pairwise discrimination, citation support, stability,
leave-one-out and matched-cost incremental-value tests pass.

The reported Buffett baseline vector `6/4/0/3/2/0` is therefore a hypothesis to audit, not an
accepted release fact. `PV3-004A` must count the physical corpus and emit
`delta_to_operational`, `delta_to_candidate` and `method_model_experiment_status`; it must not
emit a count-only `delta_to_method_model` or infer that adding `19/1/5/0/8/10` items earns that
label.

`PV3-004B` requires human adjudication against the original source for every attributed
doctrine, direct quotation, threshold and failure case. LLMs may help locate, OCR and index
candidate passages, but may not assign source grade or admission. Method authors and source
reviewers are separate, and project-derived rules remain labelled
`derived_proxy | empirical_calibration | editorial_choice`.

### Taleb real-grounding refusal is a release fixture

`PV3-107A` binds each Taleb rule to typed fact IDs and separates synthetic calculator tests
from real-data eligibility. The frozen NOK fixture evaluates four rule families:
`skew_flat`, realized volatility, friction-adjusted edge, and next earnings/event date versus
option expiry. If only `skew_flat` is computable, coverage is `1/4 = 25%`, below the 50%
minimum, so the deterministic result is `insufficient_grounding` and no narrative model is
called. Missing chain, realized-volatility, bid/ask-cost or event/expiry facts may never be
filled from model memory. A critical tradeability input can force abstention even when a
simple coverage ratio would otherwise pass.

### `N_eff` is a preregistered research diagnostic

`PV3-005A` freezes the jointly scorable error dimensions, outcome horizon, abstention and
missingness treatment, minimum sample, standardization, covariance/correlation estimator,
shrinkage, regime stratification and cluster-bootstrap confidence interval before outcomes
are inspected. Native decisions with different meanings are not coerced into one directional
label merely to make a correlation matrix.

The output is nullable. If outcomes are unresolved, the jointly scorable sample is below the
preregistered minimum, the scoring rule is not common, or the matrix is unstable, return for
example `{"n_eff": null, "reason": "insufficient_resolved_joint_sample"}`. Never return zero,
the configured seat count, or an unqualified point estimate. Until the gate passes, the UI
continues to show source clusters, unique verified contributions and materially distinct
native decisions.

A 36-company/date historical four-method pilot is nested inside the 48-case frozen benchmark.
Model self-report about knowing post-`as_of` events is diagnostic only; source-lineage checks,
future-fact detection and anonymized/reskinned cases decide whether a narrative result is
eligible. An 8-12 week forward shadow is only an **operational shadow beta** for capture,
freezing, scheduling and short-event scoring. It cannot validate long-horizon investment
calibration or promote a seat. With a 26-seat target, four pilots leave 22 seats, not the old
21-minus-4 count of 17; correlation gaps may prioritize those 22 but do not silently change
the frozen release scope.

## Runtime boundaries

- LLMs may plan research, extract cited qualitative features, challenge evidence and explain
  a frozen result.
- LLMs may not overwrite typed facts, deterministic eligibility, hard vetoes, native/common
  projection, portfolio sizing or risk limits.
- Each method receives a shared immutable fact pack plus a private evidence slice. Excluded
  evidence must be absent from the actual prompt, not merely documented as excluded.
- Native decisions are not flattened prematurely. Buffett may return
  `too_hard | reject | watch | own_at_price`; Taleb may return
  `no_trade | hedge_only | robust | convex_opportunity`. A deterministic adapter projects
  them into the council's common comparison schema.
- The first decision pass is anonymous. Names and voice are presentation metadata loaded
  after the decision is frozen.

## Release gates

0.9.0 GA is blocked until all are true:

- Exactly 26 enabled selector entries and 26 loadable v3 packs share one release manifest.
- Every selector field is localized and every pack's displayed maturity matches its actual
  admission result.
- No council entry can create a run, fetch data or spawn work without a fresh receipt.
- Every selected seat either records a decision or a deterministic `out_of_scope`; one
  missing seat makes the run incomplete and names it.
- Every material fact has unit, period, `public_at`, exact source anchor and lineage.
- Name/voice swaps move anonymous decisions by zero; policy swaps follow policy, not name.
- Counterfactual direction accuracy is at least 85%; identical-input stability is at least
  80%; blinded method identification after removing name/voice exceeds 70%.
- D13/D26 and E show preregistered material improvement over A/B/C on facts, citations,
  calibration and unique information; H supplies blinded reference and adjudication rather
  than votes. If they do not, the extra seats remain an experimental lens pack and are not
  marketed as independent intelligence.
- Count-only legacy-v2 admission is impossible; `method_model` requires the signed corpus,
  behavior, ablation and independent-increment admission artifact.
- The Taleb NOK real-grounding fixture returns `insufficient_grounding` at 1/4 coverage and
  proves no narrative model was called.
- `N_eff` is either supported by the preregistered resolved-outcome study with uncertainty or
  is serialized as `null` with a reason; insufficient samples never become zero or 26.
- Claude Code, Codex, OpenCode and Grok pass the same selection, runtime, report and package
  contract tests from an installed artifact.
- `npm run check`, generated-file freshness and every non-version/non-host readiness check
  pass before the release-candidate version change. The version is then changed atomically
  across every declared surface, and the final package, host, operation-evidence and GA gates
  all run against that exact immutable `0.9.0` candidate. A solo-test readiness pass is not GA.

## Release ceremony order

The final sequence is intentionally two-stage so that GA does not certify different bytes
from the bytes later published:

1. Keep the current `0.9.0` solo-test tree isolated and production-ineligible while human
   source/formula adjudication, all 26 production candidates and the registered
   A/B/C/D13/D26/E/H study remain incomplete.
2. Freeze a separately approved production candidate. `package.json`, Claude/Codex plugin
   metadata, marketplace metadata, `data/build-profile.v1.json` and all production pack
   versions must agree on `0.9.0`; no method, formula, corpus or policy edit is allowed after
   this point without restarting the ceremony. Version agreement alone is not GA.
3. Assemble the immutable `0.9.0` release directory and build one physical npm tarball. The
   package evidence and every external-host run must bind the same raw tarball hash.
4. Run Claude Code, Codex, OpenCode and Grok E2E against that tarball; import the physical
   fact, decision, report and quality artifacts for each host.
5. Execute the signed candidate cutover, rollback to the retained predecessor and final
   re-cutover inside the release root. This proves recoverability; it is not a public npm or
   Git tag publication.
6. Have the independent experiment adjudicator sign the physical experiment set, then have
   two independent release-evidence principals sign the complete GA evidence document.
7. Run the unified GA command against the immutable release root, exact tarball, eight
   experiment arms, four host artifacts and operation history. Only a passing post-bump GA
   authorizes a production tag/publication or public production-GA claim for `0.9.0`.
