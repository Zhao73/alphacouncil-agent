# v1.5.0 Maintainer Checklist

Every checkbox below is an owner-only action. This branch has not performed or verified any
of them. Source and tarball checks are T1/T2; the release-workflow rehearsal is T3. Registry
publication (T4) and a real installed-host run (T5) remain `not_run` until separately recorded.

## Release ownership

- [ ] **Owner-only — Bind npm Trusted Publishing.** In the npm settings for
  `alphacouncil-agent`, configure GitHub Actions for the exact repository
  `Zhao73/alphacouncil-agent`, workflow filename `release.yml` (filename only), and the
  `npm publish` action. Leave the environment field empty while
  `.github/workflows/release.yml` has no `environment`; if one is added later, make both
  values match exactly. Confirm the package's publishing-access policy before pushing a tag.

- [ ] **Owner-only — Select and tag the release commit.** After merge, fetch the destination
  branch, record the intended commit, rerun the repository checks there, and recheck npm and
  GitHub for version/release drift. Confirm that `1.5.0` is not already published and that
  `v1.5.0` does not point elsewhere. Push `v1.5.0` only from the recorded commit; do not move
  or reuse the tag to repair a failed release.

## Community ownership

- [ ] **Owner-only — Establish a private conduct-reporting route.** Provide a real private
  conduct-reporting address controlled by the maintainer before adding
  `CODE_OF_CONDUCT.md`; a public issue and the security-reporting channel are not substitutes.
  In the same future change, update or remove the temporary CoC-absence assertion in
  `test/contract/contributing.test.mjs`.

- [ ] **Owner-only — Enable GitHub Discussions.** Turn on the repository setting, choose the
  initial categories and moderation owner, and verify the public entry point. Do not describe
  Discussions as available before that setting is visibly live.

## Contract and identity ownership

- [ ] **Owner-only — Preserve the package audit contract.** Treat any future removal of
  `knowledge/ai-assisted-solo/reviews/`, host-E2E evidence, or another audit surface required
  by `scripts/check-packaged-host-parity.mjs` as a separately documented package-contract
  decision. Review the tarball inventory and consumer promise first; do not weaken parity
  checks merely to make a removal pass.

- [ ] **Owner-only — Evaluate naming overlap.** Check the AlphaCouncil name against relevant
  packages, repositories, products and marks, then record the keep-or-migrate decision. No
  repository, npm package, MCP identifier, host manifest or user command is renamed in this
  branch; any later rename needs an explicit compatibility and migration plan.

## Bounded launch

- [ ] **Owner-only — Run the bounded launch checklist with `assets/demo.mp4`.** Confirm the
  existing demo plays, contains no private data and still matches the documented first-run
  path. After the workflow succeeds, verify the npm `1.5.0` artifact, the GitHub `v1.5.0`
  release and its commit binding, then perform and record a clean Skill-first Codex install
  before making a T5 claim. Use the existing demo for the planned announcement; do not expand
  this item into an unreviewed campaign or claim four-host live evidence that was not run.

Completion evidence belongs in an owner-controlled release record. Do not mark an item done
from a green source test, a tarball smoke test, or the presence of this checklist alone.
