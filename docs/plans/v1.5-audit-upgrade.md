# v1.5 Audit Upgrade Plan — reviewed v2

This is the frozen work order produced by the 2026-08-26 joint Codex/Claude
repository review. Codex implements and tests each package locally. Claude reviews the
complete unified diff and test transcript for each local commit. The branch is pushed
only after all seven packages pass their local gates and Claude's provisional reviews;
Claude then fetches the pushed branch for the final independent review.

- Working branch: `claude/repository-audit-upgrade-69mqyp`.
- Commit the plan first, then WP1 through WP7 in order. Keep one coherent commit per
  package and do not squash or rewrite commits after review.
- Do not push, publish, tag, create a release, or represent owner-only settings as done
  until the relevant gate below explicitly permits it.
- Do not commit generated run artifacts. Do not edit `mcp/generated/` except through
  `npm run schemas:generate`.

## Global gates and evidence levels

Before every WP commit:

1. `npm run check` passes.
2. `npm run test:package` passes.
3. No runtime or development dependency is added.
4. The MCP tool names and JSON schemas remain byte-compatible: no tool is renamed and
   no schema field is removed or narrowed.
5. The change remains inside the package's stated scope.

Every report separates these evidence levels:

- **T1 — source:** source tests and repository contracts.
- **T2 — tarball:** an unpacked npm tarball and direct stdio MCP exercise.
- **T3 — release pipeline:** static validation and a non-publishing workflow rehearsal.
- **T4 — registry:** the public npm artifact and metadata.
- **T5 — host/live run:** an installed host invoking a real model-backed council run.

T4 and T5 are not validated by this branch. Green T1/T2 checks must never be reported
as a registry, four-host live-E2E, PersonaPack-v3 GA, or real-investment-result claim.

## WP1 — Security fixes

Implement every item with a regression test that fails against the old behavior and
passes against the fix.

1. In the GUI renderer, escape both quote characters as well as `&`, `<`, and `>`.
   Centralize link handling behind an explicit `safeHref` policy that accepts only
   absolute `http:` and `https:` URLs. Cover `javascript:`, `data:`, `vbscript:`,
   protocol-relative URLs, and quote-attribute injection as negative cases. The current
   markdown regex already narrows links to HTTP(S); `safeHref` is defense in depth and
   must not be described as fixing a currently accepted `javascript:` URL.
2. In `gui/server.mjs`, use `fileURLToPath` instead of URL pathname conversion. Reject
   requests with a `Host` value outside `localhost`, `127.0.0.1`, and `[::1]`, each with
   an optional valid port, with status 403.
3. Harden company-source acquisition without dependencies:
   - reject loopback, unspecified, private, link-local, metadata, ULA, IPv4-mapped IPv6,
     and non-canonical decimal/octal/hex single-integer IPv4 forms;
   - resolve every hostname and reject the destination when any answer is unsafe;
   - connect through `node:http`/`node:https` with a custom `lookup` callback that
     returns only the already-vetted, pinned address, closing DNS rebinding time-of-check
     to time-of-use;
   - follow redirects manually, re-running URL and address validation on every hop,
     with at most five hops and fail-closed lookup/error behavior;
   - retain the repository's injectable transport/resolver seams so tests are
     deterministic.

The abandoned `getQuotes` signal item is not part of WP1. Its only production caller,
`rpc.mjs`, has no abort signal to pass. Real cancellation requires end-to-end MCP
`$/cancelRequest` support and is out of scope.

**WP gate:** quote injection, unsafe schemes, Host variants, Windows path conversion,
private/encoded IPs, unsafe DNS answers, redirect hops, lookup failure, and a DNS-change
after validation all have deterministic regression coverage.

## WP2 — Package inventory and evidence-first slimming

There is no preset byte target. Unknown or ambiguous content stays in the package.

1. Capture the main-baseline `npm pack --json` inventory. Classify every shipped path
   for the review report as one of:
   - **runtime-required:** the complete static import closure of `mcp/server.mjs`, all
     individually checked dynamic `import()`/`createRequire` edges, and every runtime
     data dependency. This class must retain the build profile and its full
     `knowledge/solo-test/masters/` pack root, `knowledge/masters/`, and all data read by
     the runtime closure.
   - **audit-surface-required:** content asserted by packaged-host-parity or promised by
     a shipped skill. This class currently includes
     `knowledge/ai-assisted-solo/reviews/` and remains present.
   - **build-only:** proven to be reachable only from development/script entry points
     and absent from the first two classes.
   - **unknown:** insufficient evidence; retain it.
2. Re-derive the import closure instead of trusting the audit's module list. Move only
   proven build-only `personas-v2`/`personas-v3` modules from `mcp/lib/` to an appropriate
   development location and update source/tests/importers. Because `scripts/` is shipped,
   also use a precise pack exclusion or a narrowed publish list that makes the move
   effective. The installed `bin`, shipped npm scripts, and shipped documentation must
   not reference an excluded path.
3. Never remove an entire knowledge subtree by assumption. Preserve
   `knowledge/solo-test/masters/` and the current 26-seat runtime. Assess other
   solo-test formula material and `knowledge/ai-assisted-solo/experiments/` separately;
   exclude only a subcategory proven build-only. Preserve reviews in this release.
4. Update package parity so forbidden content is asserted absent and required runtime
   and audit surfaces are asserted present.

**WP gate:** create and unpack the tarball, then cold-start its MCP server over real
stdio. Assert `initialize`, `tools/list == 34`, `begin_council_selection` returns 26
masters, English/Chinese/Japanese/Korean localized selection fields exist, and a used
selection receipt is rejected on replay. Report before/after compressed bytes,
unpacked bytes, and file counts without treating size alone as success. If no deletion
is safely justified, a high-quality ledger plus removal of only proven redundancy is a
valid WP2 result.

Preserve existing assets and tone while making the first screen user-oriented.

1. Above the fold: banner/badges, the concise product promise, demo, three-line install,
   a free first run, a call-structure/depth table, example-report link, and disclaimer.
2. Reduce the feature comparison to five benefit-led rows. Move rather than delete
   detailed architecture material. Terms such as `full_v2`, `quick_v1`,
   `selection_receipt`, `operator_lens`, `method_model`, `analyze_symbol`,
   `plan_visible_run`, `fail-closed`, and `begin_council_selection` stay below the fold

   A measured cost may be documented only when backed by a usage artifact that names the

   of published methods pending human review, and a stance is a structured argument to
   check rather than a validated model.
5. Add a neutral comparison using only distinctions already supported by the roadmap:
   correlated-error handling, deterministic stance frozen before prose, per-claim source
   IDs, and surfaced minority reports. Do not invent competitor claims.
6. Link `assets/demo.mp4` and keep the existing visual assets.
7. Give README.md, README.zh-CN.md, and README.ja.md the same section structure and
   preserve any moved content at an addressable location under `docs/`.

**WP gate:** README.md has less than roughly 1,500 words above the reference fold; the

## WP6 — Version 1.5.0 and release automation

1. Synchronize 1.5.0 only across authoritative current-version surfaces:
   - `package.json` and the root package in `package-lock.json`;
   - `.claude-plugin/plugin.json`;
   - `.claude-plugin/marketplace.json` metadata and first plugin entry;
   - `.codex-plugin/plugin.json`;
   - `server.json` top-level and first package entry;
   - the Current Build Profile line in `CLAUDE.md`.
   Add a 1.5.0 entry to `CHANGELOG.md`. Preserve historical release/plan versions.
2. Add `.github/workflows/release.yml` for `v*` tags using npm Trusted Publishing/OIDC:
   - Node 24 and the current major of `actions/setup-node`;
   - `permissions: contents: read, id-token: write` for the publish job;
   - an explicit `npm --version` assertion for npm >=11.5.1;
   - a guard that the tag exactly equals `v` plus `package.json#version`;
   - clean install, T1/T2 checks, then `npm publish --access public` with no long-lived
     token and no token fallback. Provenance is supplied automatically by OIDC.
3. Put GitHub release creation in a separate `github-release` job with
   `needs: publish` and `contents: write`. Make it create-or-edit idempotently so
   rerunning failed jobs after a successful publish does not republish the npm version.

**WP gate:** parse the YAML, exercise the version and npm-version guards without
publishing, and inspect the two-job permission/failure semantics. This is T3 only.
