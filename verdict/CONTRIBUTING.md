# Contributing

Thanks for helping. Verdict aims to stay small, fast and honest about what it knows.

1. `npm install`, then `npm test` — the suite is offline and takes a few seconds.
2. Try your change with `verdict demo` (no key needed) and, if it touches research, a real run.
3. Keep the engine, MCP server and renderers dependency-free.
4. If the UI changes, run `npm run shots` so the README images match.
5. Add a line to `CHANGELOG.md` under an `Unreleased` heading.

Bug reports are most useful with `verdict doctor` output and the run folder from `verdict history`.
